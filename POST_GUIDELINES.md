# Research Post Guidelines

These rules apply to every research-paper review post published on this site.

## Mandatory source links

Every paper-review post must display the original sources near the top of the article, before the main technical discussion.

Required links:

1. **Original project page / GitHub Pages link** — for example, the paper's official `github.io` project page when available.
2. **arXiv abstract link** — `https://arxiv.org/abs/<paper-id>`.

Recommended when available:

3. **arXiv HTML link** — `https://arxiv.org/html/<paper-id>`.
4. **Code repository** — official GitHub repository.
5. **PDF / paper page** — official conference or journal page.

## Presentation rule

Place the source links directly below the paper-review eyebrow/title area as compact pill-style links, for example:

```html
<div class="paper-links">
  <a href="<project-page>" target="_blank" rel="noopener">Project page ↗</a>
  <a href="<arxiv-abs>" target="_blank" rel="noopener">arXiv ↗</a>
  <a href="<arxiv-html>" target="_blank" rel="noopener">HTML paper ↗</a>
</div>
```

## Bilingual rule

The English and Korean versions of the same research post must expose the same source links. Do not omit the original project page or arXiv link from either language version.

## Content rule

When summarizing a research paper, preserve clear attribution for external figures, tables, and reported experimental values. Prefer reconstructed diagrams or tables when appropriate, and label original figures with their source.

This is a standing project rule for all future research-paper posts.
