2. 리뷰 원칙

Claim ≠ Evidence. 저자들이 주장하는 contribution과 실제 실험·코드·데이터·하드웨어 결과가 입증하는 범위를 분리해서 작성한다.

전체 리뷰는 다음 세 단계로 구성한다.

  1. 논문 이해: bibliographic context, 연구 문제, contribution, method, training/inference pipeline.
  2. 증거 검증: experiments, ablation, hidden assumptions, reproducibility, result validity.
  3. 의미 판단: 연구적 영향, engineering takeaway, 재현 실험, related work, final verdict.

4. One-paragraph summary

한 문단 안에서 무슨 문제를 풀고, 핵심 아이디어가 무엇이며, 기존 방법과 무엇이 달라졌고, 가장 강한 결과가 무엇인지 설명한다.

Core idea: 핵심 기술적 전환을 한두 문장으로 요약한다.

5. 선택 사항: KPI snapshot

scale, performance, generalization, deployment를 이해하는 데 도움이 되는 3–4개의 기억할 만한 수치만 보여준다.

[Metric]이 숫자가 의미하는 것
[Scale]robots / tasks / data / model size
[Result]주요 성능 향상
[Hardware]실환경 플랫폼 또는 deployment

6. Research problem

  • 기존 방법의 한계: 무엇을 처리하지 못하는가.
  • 연구 질문: 논문이 직접 답하려는 질문은 무엇인가.
  • Task assumptions: observation/action, embodiment, supervision, simulator, object model, coordination assumption 등을 명시한다.

7. Claimed contributions

  1. 저자가 주장하는 contribution 1
  2. contribution 2
  3. contribution 3

이 섹션에서는 저자의 주장을 있는 그대로 정리하고 판단은 뒤의 Result validity에서 한다.

8. Method

8.1 Architecture / core abstraction

수식보다 먼저 system decomposition 또는 representation을 설명한다.

8.2 Inputs / outputs

ComponentInputOutputRole
[Module][Observation / state / tokens][Action / latent / command][기능]

8.3 Objective functions / reward / optimization target

방법 이해에 필요한 핵심 수식만 포함한다.

$$\mathcal{L}=\cdots$$

변수 설명: 주요 기호를 정의하고 objective가 실제 system behavior에 어떤 영향을 주는지 연결한다.

8.4 Dataset and training

dataset, simulator, collection procedure, initialization, algorithm, curriculum, losses/rewards, compute, parallelism, fine-tuning stage, frozen/trainable component를 기록한다.

Implementation detail worth remembering: 재현 시 가장 중요할 practical detail을 하나 기록한다.

8.5 Inference procedure

runtime flow를 단계별로 적고 deployment 시 실제로 사용 가능한 정보와 online component를 명확히 한다.

9. Experiments and results

중심 주장을 판단하는 데 필요한 최소한의 결과만 추린다. simulation-only evidence, real-world evidence, author-defined internal benchmark를 구분한다.

Benchmark / robotSplit / settingMetricBaselineProposedNotes

9.1 Generalization / ablation / scaling

unseen object, larger team size, new task, real hardware, robustness, ablation 등 핵심 mechanism을 가장 직접적으로 검증하는 실험을 포함한다.

10. Critical review

10.1 Strengths

  • 강한 technical idea
  • 강한 experimental evidence
  • 유용한 engineering/research property

10.2 Weaknesses

  • methodological limitation
  • evaluation limitation
  • deployment/scalability limitation

10.3 Hidden assumptions

  • privileged state / calibration / object model / frozen controller / known task structure
  • reported benchmark 밖에서는 성립하지 않을 수 있는 assumption

12. Result validity

  • 비교 조건의 공정성: baseline과 proposed가 동일 조건에서 평가됐는가?
  • 통계: sample count, variance, confidence interval, significance가 충분한가?
  • Sim / real gap: 어떤 claim이 real hardware에서 검증됐는가?
  • Benchmark independence: public/standard benchmark인지 authors/company 자체 benchmark인지 구분한다.
  • Metric validity: metric이 실제 task success나 deployment usefulness를 대표하는가?
  • Claim-to-evidence match: 어떤 claim이 strong / partial / speculative인지 구분한다.

13. Why this paper matters

어떤 capability 또는 연구 방향이 바뀌는지, 어떤 assumption이 줄었는지, VLA/RL/humanoid/manipulation/sim-to-real 맥락에서 어디에 위치하는지 설명한다.

14. Engineering takeaways

  • Reusable idea: 다른 system에 가져갈 아이디어.
  • Implementation lesson: 기억할 practical recipe.
  • Deployment implication: 실제 robot/system 적용 시 달라지는 점.
  • Main caveat: 반드시 고려해야 할 제한.

15. Experiments to reproduce

  1. 핵심 claim을 확인할 최소 재현 실험
  2. central mechanism을 분리하기 위한 ablation
  3. real-world 또는 OOD에서 해볼 가치가 있는 실험

16. Related papers

  • 가장 가까운 predecessor와 차이
  • competing approach
  • follow-up 또는 complementary work

17. Final verdict

ImpactHigh / Medium / Low — 이유
ConfidenceHigh / Medium / Low — evidence에 대한 신뢰도
Usefulness for current workHigh / Medium / Low — 구체적 활용 가능성
