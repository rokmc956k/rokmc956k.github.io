논문 정리 · Multi-Humanoid Loco-Manipulation

decMHT는 여러 humanoid가 하나의 물체를 들어 운반하고 서로 handover하는 문제를 decentralized object-centric control로 푼다. 각 robot은 동일한 local policy를 실행하고, 다른 robot의 full state나 global payload geometry를 직접 보지 않는다. 대신 자신의 local attachment specification과 local command만 받고, 실제 coordination은 shared payload를 통해 간접적으로 일어난다.

1. 왜 multi-humanoid transport가 어려운가?

이 문제는 balance, locomotion, hand contact, load support, object tracking, teammate interaction force가 동시에 얽힌다. centralized controller는 모든 robot state와 action을 묶어 최적화할 수 있지만, robot 수가 늘수록 observation/action dimension이 커지고 특정 team configuration에 구조적으로 묶이기 쉽다.

decMHT의 질문: 전체 multi-robot state가 아니라 object interface를 중심으로 policy를 정의하면 각 humanoid가 자신의 local contribution만 해결하면서도 팀 전체가 협력할 수 있는가?

2. Object-centric attachment specification

robot $r$의 local attachment specification은 다음과 같다.

$$\mathcal{A}^{(r)} = \left({}^{b}T^{(r)},\, w^{(r)},\, d^{(r)}\right).$$

$${}^{b}T^{(r)}\in SE(3)$$는 torso frame 기준 attachment frame pose, $w^{(r)}$는 양손 contact offset, $d^{(r)}$는 접근 시 torso clearance다. 중요한 점은 full object mesh나 다른 robot의 상태를 입력하지 않고 자기 attachment 주변의 local geometric specification만 사용한다는 것이다.

이 리뷰를 위해 재구성한 개념도. 실제 방법은 robot별로 local attachment frame을 지정한다.

3. 하나의 payload command를 robot별 local command로 변환

task-level payload command는

$$\mathcal{C}_{\mathrm{pl}} = (v_x, v_y, \omega_z, h)$$

로 표현된다. payload의 planar velocity, yaw rate, height를 의미한다. 각 robot은 자신의 attachment offset을 이용해 local command frame의 속도로 변환한다.

$$v^{(r)}_{\mathrm{cf}} = v_{\mathrm{pl}} + \omega_{\mathrm{pl}} \times p^{(r)}_{\mathrm{offset}},$$

$$\omega^{(r)}_{\mathrm{cf}} = \omega_{\mathrm{pl}}, \qquad h^{(r)}_{\mathrm{cf}} = h_{\mathrm{pl}} + p^{(r)}_{\mathrm{offset},z}.$$

즉 planner는 하나의 rigid payload만 생각하고, 각 humanoid는 자신이 붙어 있는 위치에서 필요한 local motion만 받는다. 이 분해가 team size 변화에 대한 scaling의 핵심이다.

4. Hierarchical decentralized controller

각 humanoid는 high-level loco-manipulation policy와 frozen low-level locomotion policy를 사용한다. low-level policy는 proprioception과 base motion target을 leg joint target으로 변환한다.

$$q^{(r)}_{\mathrm{leg}} = \pi_l\left(s^{(r)}, v_x^{(r)}, v_y^{(r)}, \omega_z^{(r)}, h^{(r)}\right).$$

high-level policy는 arm target과 base motion target을 동시에 생성한다.

$$\left(q^{(r)}_{\mathrm{arm}},v_x^{(r)},v_y^{(r)},\omega_z^{(r)},h^{(r)}\right) = \pi_h\left(s^{(r)},\mathcal{A}^{(r)},\mathcal{C}^{(r)}_{\mathrm{cf}},m^{(r)}\right).$$

5. Mode-gated behavior: idle / track

binary mode flag $m^{(r)}\in\{\texttt{idle},\texttt{track}\}$를 사용해 하나의 network가 참여/비참여 behavior를 모두 표현한다.

$$R^{(r)} = \mathbf{1}[m^{(r)}=\texttt{idle}]R_{\mathrm{idle}} + \mathbf{1}[m^{(r)}=\texttt{track}]R_{\mathrm{track}}.$$

6. Independent PPO와 curriculum

high-level policy는 Independent PPO(IPPO)로 학습한다. 먼저 single-robot manipulation에서 기본 skill을 학습한 뒤, 같은 shared policy를 two-robot cooperative episode로 fine-tune한다. deployment에서는 이 policy copy를 각 robot이 독립적으로 실행한다.

7. Zero-shot scaling 결과

가장 강한 결과는 policy를 최대 두 robot으로만 학습하고도 evaluation에서 10대 humanoid까지 zero-shot으로 확장한다는 점이다.

8. Unseen object와 50 kg payload

학습 payload 범위를 벗어난 cabinet, fridge, log, bed, concrete slab 같은 geometry에서도 generalization을 평가한다. team size를 늘리면 simulation에서 최대 50 kg payload까지 운반한다.

특히 bed task에서는 single-robot-only training policy가 44.1% pickup success에 머문 반면, two-robot cooperative fine-tuning 이후 decMHT는 85.2%까지 올라간다. 이는 cooperative dynamics를 실제로 학습하는 단계가 필요함을 보여준다.

9. Cost of Transport 관점

효율성은 흔히 Cost of Transport로 비교할 수 있다.

$$\mathrm{CoT}=\frac{E}{m g d}$$

여기서 $E$는 이동 중 소비 에너지, $m$은 전체 이동 질량, $d$는 이동 거리다. multi-robot transport에서는 단순 success뿐 아니라 robot 수 증가에 따른 energy efficiency와 load distribution도 함께 보는 것이 중요하다.

10. Sim-to-real: Digit V3

학습 policy는 Digit V3 hardware로 transfer되어 single-robot transport, dual-robot cooperative transport, handover를 수행한다. 이 점은 decMHT의 object-centric abstraction이 simulation에서만 유효한 coordination trick이 아니라 실제 hardware에서도 활용 가능한 interface임을 보여준다.

11. 연구 관점의 핵심 takeaway

가장 중요한 아이디어: team-level coordination을 explicit communication이나 centralized state estimation으로 만들지 않고, shared object dynamics 자체를 coordination channel로 사용한다.
  • Scalability: global team dimension에 직접 의존하지 않는 local policy라서 robot 수 변화에 강하다.
  • Composability: attachment specification과 mode switching만 바꿔 pickup, transport, handover를 같은 policy로 표현한다.
  • Hierarchical prior: frozen locomotion policy를 유지해 high-level manipulation learning의 난이도를 줄인다.
  • Limit: attachment assignment와 high-level payload command를 제공하는 상위 planning layer는 여전히 필요하다.
  • Industrial implication: 장척물, 대형 부품, 유연한 team size가 필요한 cooperative handling에 특히 흥미로운 구조다.
