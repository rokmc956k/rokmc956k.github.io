InterEvolve는 새로운 humanoid loco-manipulation task가 들어왔을 때 controller를 다시 학습시키는 대신, task를 표현하는 reward program 자체를 test time에 진화시키는 방법이다. 핵심 아이디어는 이미 넓은 motor repertoire를 가진 behavioral foundation model이 있다면, 새로운 행동을 만들기 위해 policy weights를 바꾸는 대신 그 능력을 꺼내는 task interface를 바꾸자는 것이다.

핵심 한 줄: controller는 고정하고, LLM이 multi-stage reward program의 구조를 수정하며 CMA-ES가 숫자 파라미터를 튜닝한다. 실행 결과는 fixed verifier가 평가하고, 성공한 program은 skill library에 저장된다.

1. 왜 reward program인가?

기존 humanoid control interface는 motion reference, goal state, skill label처럼 “무엇을 따라갈지”를 직접 지정하는 경우가 많다. 하지만 box를 기울여 다른 면으로 세우기, 좁은 gate 사이로 밀기, 손을 쓰지 않고 발로 차기 같은 접촉 중심 task는 단일 goal state만으로는 행동 전략을 충분히 표현하기 어렵다.

InterEvolve는 task를 여러 stage로 분해하고 각 stage마다 reward와 종료 조건을 부여한다. reward program은 다음과 같이 쓸 수 있다.

\[ P = \left(\boldsymbol{\theta},\{(r_j,g_j)\}_{j=1}^{J}\right) \]

여기서 $r_j$는 stage $j$의 reward function, $g_j$는 stage completion condition, $\boldsymbol{\theta}$는 reward weight, tolerance, kernel width, threshold와 같은 tunable constants다. 예를 들어 “box에 접근 → 두 손 접촉 → 들어올림 → 이동 → 내려놓고 손 떼기”를 하나의 program으로 표현할 수 있다.

2. Forward–Backward behavioral foundation model

reward를 바꿀 때마다 RL을 다시 돌리면 reward search 자체가 너무 느려진다. InterEvolve는 이를 피하기 위해 forward–backward(FB) representation을 사용한다. latent $\boldsymbol z$가 하나의 policy behavior를 가리키고, forward map $F$와 backward map $B$가 discounted future-state occupancy를 factorize한다.

\[ M^{\pi_{\boldsymbol z}}(d\boldsymbol s'\mid \boldsymbol s,\boldsymbol a) \approx F(\boldsymbol s,\boldsymbol a,\boldsymbol z)^\top B(\boldsymbol s')\,\rho(d\boldsymbol s') \]

그러면 새로운 reward $r$에 대한 action value는 다음처럼 latent projection으로 근사된다.

\[ Q_r^{\pi_{\boldsymbol z}}(\boldsymbol s,\boldsymbol a) \approx F(\boldsymbol s,\boldsymbol a,\boldsymbol z)^\top \widetilde{\boldsymbol z}_r, \qquad \widetilde{\boldsymbol z}_r = \mathbb E_{\rho}\left[r(\boldsymbol s')B(\boldsymbol s')\right] \]

중요한 점은 새 reward가 들어와도 policy를 재학습하지 않고 latent prompt만 다시 계산한다는 것이다. 이것이 reward program을 여러 번 수정하고 바로 rollout으로 검증할 수 있게 해준다.

Reward inference bank와 reward tilt

실제 시스템은 pretraining replay에서 뽑은 state bank $\mathcal B=\{\boldsymbol s_n\}_{n=1}^{N}$를 고정해 두고, 각 stage reward를 bank state에 평가해 latent prompt를 만든다.

\[ \boldsymbol z_{j,t}= \operatorname{proj}\left( \sum_{n=1}^{N}\alpha_{j,n,t}B(\boldsymbol s_n) \right), \qquad \alpha_{j,n,t}\propto \hat r_{j,n,t}\exp(\beta\hat r_{j,n,t}) \]

$\beta$는 high-reward states에 얼마나 강하게 집중할지를 정한다. kicking처럼 training data에서 드문 행동은 관련 state가 적기 때문에 uniform averaging보다 적절한 reward tilt가 중요하다.

3. Object-aware residual: body prior는 얼리고 object interaction만 확장

기존 body-only FB model은 robot body motion은 잘 표현해도 “같은 body motion인데 object goal만 다른” task를 구분하기 어렵다. InterEvolve는 body prior를 freeze한 채 object-conditioned residual branch를 actor, forward map, backward map에 추가한다.

\[ \boldsymbol\mu_{\pi}(\boldsymbol o_t,\boldsymbol z) = \tanh\!\left( \boldsymbol\mu_{\mathrm{prior}}(\boldsymbol o^{\mathrm{body}}_t,\boldsymbol z) + \boldsymbol\Delta_{\mu}(\boldsymbol o_t,\boldsymbol z) \right) \]

여기서 $\boldsymbol\mu_{\mathrm{prior}}$는 frozen body behavior를 보존하고, $\boldsymbol\Delta_{\mu}$가 object position/orientation/velocity와 body-link-to-object geometry를 사용해 interaction을 보정한다. 구조적으로 보면 BC/RL residual policy와 비슷한 분업이다. 큰 motor prior는 유지하고 object interaction competence만 residual branch에 학습한다.

4. 핵심 알고리즘: LLM outer loop + CMA-ES inner loop

InterEvolve의 search는 두 종류의 변수를 분리한다.

  • Structure: 어떤 stage를 둘지, 어떤 reward term을 쓸지, 언제 stage를 넘어갈지 → LLM agent가 수정
  • Constants $\boldsymbol\theta$: reward weights, thresholds, tolerances → CMA-ES가 numerical search

각 candidate는 하나의 scenario가 아니라 여러 randomized scenario에서 parallel rollout된다. verifier는 reward program과 독립적으로 고정되어 있어, agent가 evaluator 자체를 느슨하게 바꾸는 것을 막는다. candidate가 현재 best program보다 충분히 좋아졌을 때만 교체되고, 최종 program은 skill library에 저장된다.

7. Skill library: test-time 경험을 weight가 아니라 program으로 축적

성공한 reward program은 scene, verifier 결과, tuned constants와 함께 text 형태의 skill library에 저장된다. 이후 새로운 task에서 LLM은 이 program들을 retrieve해서 복사하거나 조합하거나 수정한다. 예를 들어 “push → release → kick” 같은 composite task는 이전 push/kick program을 재사용해 search를 시작할 수 있다.

이 부분이 흥미로운 이유는 skill accumulation이 neural weights 안에만 존재하지 않는다는 점이다. controller는 그대로이고, inspectable task knowledge가 reward program이라는 외부 표현으로 축적된다. 따라서 planning/reasoning과 motor control의 update timescale을 분리할 수 있다.

8. Generalization과 real Unitree G1 deployment

project page에서는 동일 reward program을 goal 위치나 initial box pose를 바꿔도 그대로 실행하고, large box에서 얻은 program을 plastic box, small box, suitcase로 adaptation하는 결과를 보여준다. 또한 selected programs는 physical Unitree G1에서 egocentric RGB-D perception과 object pose estimation을 사용해 실행된다.

실제 robot에서는 torso RGB-D, FastSAM/CLIP 기반 box detection, FoundationPose 기반 6-D pose tracking, LiDAR 및 contact/floor constraints를 결합한 state estimation을 사용하며 controller는 50 Hz로 동작한다.

9. 이 논문의 의미

  • Policy learning과 task adaptation을 분리했다. motor model은 한 번 pretrain하고, 새로운 task는 reward program search로 푼다.
  • Test-time compute를 robotics에 명확하게 적용했다. 더 많은 rollout과 program revision이 더 나은 task solution으로 연결된다.
  • Reward는 training signal뿐 아니라 control interface가 될 수 있다. FB representation 덕분에 reward가 즉시 latent prompt로 변환된다.
  • Multi-stage structure가 매우 중요하다. contact-rich task는 single reward보다 phase decomposition이 훨씬 강하다.
  • Skill memory가 text/program 형태로 남는다. 이후 task에서 inspectable하고 재사용 가능한 experience가 된다.

10. 한계와 내가 보는 핵심 질문

저자들이 명시한 가장 큰 한계는 reward evolution이 이미 controller가 가진 motor repertoire와 reward-inference bank의 coverage를 넘을 수 없다는 것이다. 실제로 kicking처럼 pretraining에서 희소한 behavior의 성능은 상대적으로 낮다. 또한 한 task family의 full evolution에 약 2.1 GPU-hours와 LLM inference가 필요해 physical execution 중 real-time replanning 용도로는 아직 어렵다.

Research takeaway: 이 접근은 “foundation policy를 계속 fine-tune해야 하는가?”에 다른 답을 준다. 충분히 넓은 motor prior가 있다면, task-specific learning의 일부를 weight update가 아니라 reward-program search로 옮길 수 있다. 앞으로는 이 reward-program layer와 VLA planner, residual RL, real-world online adaptation을 어떻게 연결할지가 중요한 연구 포인트다.
